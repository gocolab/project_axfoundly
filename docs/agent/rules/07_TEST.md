# 07. 테스트 전략

> 문서 상태: ✅ 완료

## 1. 테스트 범위

### 작성할 테스트 수준
- 상태: ✅ 결정
- 선택지: 단위 / 통합 / E2E / 없음
- 결정: E2E 테스트 및 API 통합 테스트
- 이유: 사용자 관점의 전체 비즈니스 흐름(인증, 결제, IR 팀빌딩, 게시판, 대시보드)과 백엔드 엔드포인트를 신속하고 완결성 있게 검증하기 위함
- 결정일: 2026-08-14

### 테스트 우선순위 (무엇을 반드시 테스트하는가)
- 상태: ✅ 결정
- 결정:
  - 역할 기반 접근 제어 (RBAC: 수강생, 강사, 투자자, 관리자 권한 격리 및 메뉴 활성화)
  - 결제 및 수강신청 인터랙션 (PG 연동 및 결제 처리 모달)
  - IR 스타트업 팀빌딩 지원 및 투자 제안 플로우
  - 멀티 커뮤니티 게시글 작성 및 필터링
  - 백엔드 REST API 헬스체크 및 Gemini AI 엔드포인트 무결성
- 이유: 플랫폼 핵심 비즈니스 가치 창출 경로(Critical Path)의 무결성 확보
- 결정일: 2026-08-14

## 2. 도구

- 결정: Playwright (`@playwright/test`)
- 이유: 에이전트 브라우저 자동화, Headless/UI 모드, 스크린샷/트레이스 캡처 및 UI/API E2E 검증 통합 지원
- 결정일: 2026-08-12

### 테스트 DB / 외부 의존성 처리
- 상태: ✅ 결정
- 선택지: 인메모리 DB / Testcontainers / 모킹 / 실제 개발 DB
- 결정: 프론트엔드 목 데이터(Mock Data) 및 백엔드 Express 모의 API / Google GenAI SDK 클라이언트
- 이유: 외부 의존성 없이 빠르고 결정론적인(deterministic) E2E 테스트 보장
- 결정일: 2026-08-14
