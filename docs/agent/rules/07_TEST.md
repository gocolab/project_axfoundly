# 07. 테스트 전략

> 문서 상태: ✅ 완료 (2026-08-05)
> 학원 체크리스트 TDD 요건 대응. CI가 없으므로 로컬 통과가 유일한 게이트 — 실행 시점 규칙 준수 필수.

## 1. 테스트 범위

### 작성할 테스트 수준
- 상태: ✅ 결정
- 선택지: 단위 / 통합 / E2E / 없음
- 결정: **단위 + 통합** — 도메인 로직 단위 테스트, API·DB 연동 통합 테스트. E2E(브라우저 시나리오)는 수동 확인
- 이유: TDD 요건 충족 + 4주 일정 현실성 (2026-08-05 인터뷰)
- 결정일: 2026-08-05

### 테스트 우선순위 (무엇을 반드시 테스트하는가)
- 상태: ✅ 결정
- 결정: **필수** — 출결 판정·예외처리(오전반/오후반·외출·조퇴·병결), 문자 발송 이중 조건(퇴실 미체크 AND 퇴실 시간대 영상 식별 포착 — 2026-08-05 정정, 99 참조), 개인정보 삭제 로직(퇴실 플러시·TTL 설정). **선택** — UI 컴포넌트
- 이유: 판정 오류·개인정보 잔류가 이 시스템의 최대 리스크
- 결정일: 2026-08-05

## 2. 도구

### 테스트 프레임워크
- 상태: ✅ 결정
- 결정: Spring = JUnit 5 + AssertJ / FastAPI = pytest / 프론트 = Vitest
- 결정일: 2026-08-05

### 테스트 DB / 외부 의존성 처리
- 상태: ✅ 결정
- 선택지: 인메모리 DB / Testcontainers / 모킹 / 실제 개발 DB
- 결정: 단위 = 모킹, 통합 = 학원 GPU 서버에 **별도 테스트 DB**(예: `project3_test`) — 개발 DB와 분리해 데이터 오염 방지. LMS API·문자 발송은 항상 모킹(실발송 금지)
- 결정일: 2026-08-05
